# 环节 0:整理录像

- **执行者**:AI
- **开工条件**:`db.py next` 出现 `0-整理`(`待加工/` 里有已录完、未整理的录像)。
- **先读**:`1-流程/业务流程.md` §1。

## 步骤
1. 看计划(只读,不改文件):`python3 3-工具/脚本/intake.py`
   它会列出每个文件的日期、开始时间、时长,以及时间是从哪里判断的。
2. 把文件分成"场":同一天、时间上前后相接(间隔不超过 3 小时)的分段录像算同一场;其余各自一场。
3. 定每一场的来源(课程 / 直播 / 访谈 / 论坛,见 `配置.来源类型`):
   - 用户在对话里说过的,照用户说的。
   - 没说过:用 `配置.默认来源`,并在汇报里写明"来源按默认值,如不对请告诉我"。
   - 标了"可能属于前一天"的文件:先不处理,写进汇报,等用户说明。
4. 每一场先登记素材(状态 = 待整理),记下输出的素材 ID:
   `python3 3-工具/db.py add-source --来源 课程 --日期 YYYY-MM-DD --标题 "<日期> <来源>" --本地文件夹 "工作区/<素材ID>" --状态 待整理 --by AI`
   同一天同来源有多场:加 `--序号 2`。素材 ID 规则:`课-YYYYMMDD`、`直-YYYYMMDD`、第二场 `课-YYYYMMDD-2`。
5. 整理这一场的文件:
   `python3 3-工具/脚本/intake.py --run --source-id <素材ID> "<文件1>" "<文件2>"`
6. 成功:`python3 3-工具/db.py set source <素材ID> 已整理 --by AI`
   失败(例如 mkv 无法无损转换):`python3 3-工具/db.py set source <素材ID> 需人工 --by AI --note "<原因>"`,继续下一场。

## 完成判据
- `工作区/<素材ID>/转录文件/` 里有可处理的视频(mp4 或指向原片的链接),原片在 `待加工/已处理/<素材ID>/`;素材状态 = 已整理。

## 红线
- 绝不删除原始录像;不覆盖已有文件;不自动转码重压。

## 结束行
`【完成】0-整理｜N 场已整理(素材 ID…),M 个文件跳过(原因)` / `【需人工】…` / `【失败】…` / `【无事】…`
