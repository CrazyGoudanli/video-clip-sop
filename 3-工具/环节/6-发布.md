# 环节 6:定时发布

- **执行者**:AI(浏览器自动化,见 `3-工具/工具说明/发布_浏览器.md`);登录、扫码、验证码由用户处理。
- **开工条件**:有状态 = 待发布、平台在 配置.发布平台 里的记录。"待发布"= 用户已授权。
- **先读**:`2-标准/平台规则.md`。

## 步骤
1. 排期:`python3 3-工具/db.py plan-slots`
   - `SLOT <ID> <时间> 排定/已填`:用这个时间。
   - `FULL <ID>`:`set pub <ID> 需人工 --by AI --note "14 天内无空位"`。
2. 逐条:按工具说明在平台上传成片 → 填标题、简介、话题 → 传封面 → 声明等设置 → **设定时**。
3. **提交前核对**:页面明确处于定时发布模式(以平台说明为准;抖音的按钮在定时模式下仍叫"发布")、日期时间与排定一致、封面已生效。不满足或不确定就**不提交**,标需人工。
4. 提交后必须看到成功提示,或在平台的定时列表里看到该作品;否则标需人工。
   **每次在平台后台亲眼核对后都记一笔**(工作台的"上次核对"一栏):
   `python3 3-工具/db.py checked <ID> "在<页面>看到『定时发布 MM-DD HH:MM』"`
5. 成功:`python3 3-工具/db.py update pub <ID> 发布时间="YYYY-MM-DDTHH:MM:00+08:00" --by AI`,
   再 `python3 3-工具/db.py set pub <ID> 已定时 --by AI --note "定时 MM-DD HH:MM;链接待发布后回填"`。

## 铁律
- **只定时,绝不点"立即发布/发表/立即投稿"。**
- 登录失效(如视频号跳到扫码页)、验证码、风控:`set pub <ID> 需人工 --by AI --note "<平台>登录已失效,请扫码"`(原因里写清是哪个平台、要做什么,工作台会给一键打开登录页的按钮);先输出 `【需人工】6-发布｜<平台>需要你<扫码/处理验证码>`,等用户处理;绝不代填账号密码。
- 单条出错重试 1 次仍失败,标需人工并继续其他条。

## 结束行
`【完成】6-发布｜N 条已定时(最近一条 MM-DD HH:MM),M 条需人工` / `【需人工】…` / `【失败】…`
